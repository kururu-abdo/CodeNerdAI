# CodeNerdAI

A supervised coding agent for projects you are authorized to edit. It accepts a task, inspects files, proposes edits in a temporary copy, runs a configured test command inside Docker, shows a diff, and asks before applying changes.

## Quick start

Requirements: Python 3.10+, Docker for running tests, an OpenAI API key, and a disposable checkout. Keep secrets out of the project and get client permission before sending source code to a model provider.

```bash
export OPENAI_API_KEY='your-key'
python3 codenerd.py /absolute/path/to/project 'Fix the cart total calculation' \
  --test-command 'python -m unittest discover -s tests'
```

The default model is `gpt-4.1`. Override with `--model` if needed. The Docker test image defaults to `python:3.12-slim`; pull it before running, or pass `--test-image` with a local image containing your dependencies. Tests have no network, a read-only project mount, dropped capabilities and resource limits. The test command is operator supplied, never generated by the model. For Flutter use an image with the Flutter SDK and a compatible command. Run `python3 codenerd.py --help` for all options.

Edits stay in a temporary project copy until you approve the printed diff. Without approval they are discarded. The optional `--yes` flag applies automatically and should be reserved for disposable projects. There is a 20-step default limit. This is an MVP, not a complete security boundary: run on an isolated machine, use least privilege, inspect output and run your own review and CI before delivery. Copying large repos is slow; paths in ignored folders are unavailable to the agent. The tool does not delete files, fetch dependencies, publish code, sign contracts, or contact clients.

## Launch as a service

1. Create your own verified freelancer or agency account under your real identity. Describe CodeNerdAI as your AI-assisted development workflow; you remain responsible for scope and delivery.
2. Pick one narrow offer, such as Flutter bug fixes with reproducible tests. Define input requirements, price, turnaround and excluded work.
3. Obtain client authorization to use an external model on their code and a safe repository snapshot. Never put production credentials in the snapshot.
4. Run CodeNerdAI on the snapshot, inspect the diff, run independent tests and manual QA, and deliver the reviewed result through the marketplace's allowed workflow.
5. Track acceptance rate, rework time, model cost, elapsed time, client satisfaction and profit on 10 pilot tasks before expanding offers.
6. For platform integrations, verify current rules and use only approved APIs; human review remains required for proposals, pricing, contracts and delivery.

## Production backlog

Client workspace isolation, secret scanning before model calls, dependency-aware test containers, persistent task/audit store, cost limits, resumable runs, policy per marketplace, evaluation suite, and a web intake/review dashboard. The present CLI does not claim these features.
